# RF-03 · Publicar y consultar franjas de sala

**Requerimiento:** El Administrador publica a mano las franjas de disponibilidad de la sala (con una plantilla sugerida editable), registra cierres y ajusta los parámetros de reserva. Visitantes, clientes y personal consultan el calendario en vista semanal (por defecto) o mensual.

| Campo | Valor |
|---|---|
| Caso de uso | CUS-03 Publicar y consultar franjas de sala |
| Actores | Administrador, Visitante, Artista/Cliente, Personal interno |
| Módulo backend | `reservas` ([backend-hexagonal](../01-arquitectura/backend-hexagonal.md#módulos-del-backend)) |
| Isla frontend | Calendario (`<bugalu-calendario>`), publicación de franjas ([frontend-islas](../01-arquitectura/frontend-islas.md)) |

## Criterios de aceptación

| ID | Criterio |
|---|---|
| CA-01 | Existe la sala de la sede La Molina; el modelo admite más salas sin cambiar el contrato. |
| CA-02 | Al publicar una semana, el Administrador recibe una plantilla sugerida (la última semana publicada desplazada, o vacía) que edita antes de publicar; las franjas de una misma sala no se solapan (409). |
| CA-03 | El Administrador cierra un día u horas con motivo (feriado, mantenimiento); si dentro hay reservas vigentes, se rechaza (409) y se listan. Abrir horas extra es publicar una franja más. |
| CA-04 | Una franja se retira solo si no tiene reservas vigentes (409). |
| CA-05 | La disponibilidad de un rango (una semana o un mes, hasta 42 días) devuelve las franjas, los tramos ocupados (reserva + buffer) y, por día, los minutos libres reservables (≥ 30 min, respetando anticipación mínima y máxima). Una `Pre-reservada` vencida cuenta como libre aunque aún no esté marcada. |
| CA-06 | Visitante y cliente ven ocupado sin datos de nadie; el cliente ve además sus reservas; personal y Administrador ven cliente, servicio y estado de cada reserva. |
| CA-07 | El Administrador consulta y ajusta los parámetros (plazo largo en días, plazo corto en horas, anticipación mínima en horas y máxima en semanas) con valores válidos (enteros > 0). |
| CA-08 | Interfaz: vista semanal por defecto y mensual con las mismas cifras; cada día del mes muestra en texto sus horas libres y abre su semana; ninguna disponibilidad se comunica solo por color. |
| CA-09 | Casos de rotura: 401/403 en lo del Administrador; rangos inválidos o excesivos → 422; servicio de claves o base caídos → 503; nunca 500. |

## Contrato API

Base `/api/v1`. Fechas en ISO 8601 con zona horaria; "día" y "semana" en hora de Lima ([convenciones](../01-arquitectura/convenciones.md#api)).

| Método y ruta | Acceso | Cuerpo | Respuesta | Errores |
|---|---|---|---|---|
| `GET /salas` | público | — | 200 `[Sala]` | 503 |
| `GET /disponibilidad?sala=&desde=&hasta=` | público (más detalle con token de personal o administrador) | — | 200 `Disponibilidad` | 404, 422 `rango_invalido`, 503 |
| `GET /franjas/sugerencia?sala=&semana=AAAA-Www` | administrador | — | 200 `[{inicio, fin}]` | 401, 403, 422 |
| `POST /franjas` | administrador | `{id_sala, franjas: [{inicio, fin}]}` | 201 `[Franja]` | 401, 403, 409 `franja_solapada`, 422 |
| `DELETE /franjas/{id}` | administrador | — | 204 | 401, 403, 404, 409 `franja_con_reservas` |
| `POST /cierres` | administrador | `{id_sala, inicio, fin, motivo}` | 201 `Cierre` | 401, 403, 409 `cierre_con_reservas` (lista las reservas), 422 |
| `DELETE /cierres/{id}` | administrador | — | 204 | 401, 403, 404 |
| `GET /parametros` / `PATCH /parametros` | administrador | `{dias_limite_pago?, horas_limite_pago?, anticipacion_minima_horas?, anticipacion_maxima_semanas?}` | 200 `Parametros` | 401, 403, 422 |

- `Disponibilidad`: `{franjas: [{id, inicio, fin}], ocupados: [{inicio, fin, propia, detalle?}], cierres: [{inicio, fin, motivo}], dias: [{fecha, minutos_libres}]}`. `propia` es true en las reservas del cliente autenticado; `detalle` (`{id_reserva, cliente, servicio, estado}`) solo para personal y Administrador.
